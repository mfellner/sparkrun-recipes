# GLM-5.3 Flash EXL3 dual-Spark 1M acceptance evidence

This directory preserves the raw/source evidence for the SparkRun 1M refresh audited from MiaAI-Lab commit `32db610d9207a42e2688a6994d3bfaf7af96eecb`.

## Process boundary

Two mechanically separated processes are present because the independent static audit required the runtime patch order and long-hook lifecycle to be corrected after the expensive suite:

1. **Precursor performance/long-stress process** — SparkRun `sparkrun_88b110d8c27f0455_73f56777180a`, recipe SHA-256 `da5c462d2322daf42449ac1996079f9af3f3bd9d1491bf819c718ac67789b1a6`. It used the same image, target/draft revisions, serve command, 1M memory profile and core performance patches as the final recipe; the later final process adds lifecycle, preflight, video, stop-guard and XGrammar correctness overlays. It produced the benchmark, telemetry, 3×256K and 950K receipts.
2. **Exact final process** — SparkRun `sparkrun_d56463b6b176dd58_009b8bd44277`, recipe SHA-256 `55526841b848320c66bb631f569e70a972f9261512b2cb4f05c79cc7286ec7f3`, launched by SparkRun 0.3.6 with upstream GID/video/warm-restart/XGrammar/override changes, the 3,600-second in-container fail-closed gate, and the locally gated deterministic default-thinking stop policy. The committed evidence retains final positive live behavior and enabled/opt-out unit paths, not a raw pre-fix live response.

The expensive 3×256K and 950K requests were **not** repeated on the final process; they remain explicitly scoped to the precursor above.

The rank-0 gate, final direct/proxy matrix, exact final-line stop-policy test and XGrammar C4 then passed.

## Integrity and reproduction

- `run-manifest.json` defines immutable precursor/final process records and assigns every benchmark, telemetry, acceptance, summary and runtime artifact an explicit process ID.
- `SHA256SUMS` covers every committed source, fixture, result, summary and raw artifact except itself.
- No committed verifier is advertised. Reviewers should run `sha256sum -c SHA256SUMS`, validate/dry-run the recipe, then independently recompute claims from the preserved raw rows and requests.
